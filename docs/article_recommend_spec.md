# 用户个性化推荐文章接口 规格文档

## 目标

为前台门户提供"猜你喜欢"类推荐能力：每个用户看到的内容尽量不同，同时保证
最新发布与高热度文稿有更高概率被推荐。本次只交付后端接口，前端展示不在本规格范围内。

## 数据来源

- `articles`（status = published 的已发布文稿）
- `view_history`（登录用户最近观看记录，用于构建用户偏好画像）
- `user_actions`（action_type = dislike 的不感兴趣记录，推荐时排除）

## 接口契约

### GET /api/articles/recommend

可选登录（携带 Token 则个性化，未携带则按通用热门+新鲜推荐）。

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 校验 | 说明 |
| --- | --- | --- | --- | --- | --- |
| limit | int | 否 | 8 | 1~20 | 返回推荐文稿数量，越界返回 422 |

**成功响应（200）**

```json
{
  "items": [
    {
      "id": 1,
      "title": "...",
      "summary": "...",
      "cover_url": "...",
      "view_count": 100,
      "like_count": 10,
      "favorite_count": 2,
      "share_count": 1,
      "categories": [{"id": 1, "name": "金融", "slug": "finance", "sort_order": 0}],
      "published_at": "2026-08-15 10:00:00"
    }
  ],
  "total": 8
}
```

响应字段复用 `Article.to_dict()`（不含正文/审核记录）。`total` 为实际返回条数
（候选不足 limit 时返回全部）。

**错误语义**

- 400：暂无任何已发布文稿可推荐
- 422：limit 不在 1~20 区间

## 推荐算法（混合加权评分 + 随机扰动 + 分类多样性）

### 1. 候选集

全部 `status == "published"` 的文稿；若为登录用户，额外排除：

- 已观看过的文稿（`view_history` 中存在记录）
- 已标记不感兴趣的文稿（`user_actions.action_type == "dislike"`）

### 2. 用户偏好画像（仅登录用户）

- 取最近 20 条观看记录（按 `viewed_at` 倒序），统计其所属栏目出现次数
- `pref[category_id] = 出现次数 / 20`，得到 0~1 的栏目偏好权重
- 无观看历史时画像为空，退化为通用推荐

### 3. 单篇文章评分

- 新鲜度 `fresh = exp(-age_days / 30)`：age_days 为距发布的天数，30 天内衰减明显，
  越新分数越高
- 热度 `hot`：`raw = view_count + 3*like_count + 5*favorite_count + 2*share_count`，
  在候选集内做 min-max 归一化到 0~1
- 偏好分 `pref_score = max(pref[cid])`：取文章所属栏目中用户偏好最高的栏目权重
- 基础分 `base = 0.30 * pref_score + 0.40 * fresh + 0.30 * hot`（新热合计权重 0.7，
  略高于个性化，符合"最新最热权重稍高"）
- 随机扰动 `score = base * (0.75 + 0.5 * rand)`：rand 为每次请求对每篇文章独立生成的
  [0,1) 随机数，保证不同用户/不同请求看到的内容与顺序不同

### 4. 分类多样性（贪心重排）

按 score 降序贪心选取，每选中一篇，其所属栏目中已入选篇数 k 会使该栏目剩余候选
得分乘以 `0.8 ** k`，避免 8 篇推荐全来自同一栏目。

## 前端交互

本接口为纯后端能力，前端（门户首页/相关推荐位）后续按需接入，不改变任何现有页面。

## 成功标准

1. 未登录调用返回推荐列表，条数 = min(limit, 候选数)，且全部为已发布文稿
2. 登录用户调用后，结果不包含其已观看或已标记不感兴趣的文稿
3. limit 越界返回 422；无候选返回 400
4. 同一用户连续两次请求结果不一定相同（随机扰动生效）
5. `smoke_test.py` 新增对应断言并跑通
