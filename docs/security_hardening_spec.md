# 生产安全与项目一致性加固规格

## 目标

1. 防止 `backend/.env` 被加入 Docker 构建上下文或镜像层。
2. 对编辑器、Excel 导入和智能采编写入的文稿 HTML 统一执行允许列表清洗，并在读取历史文稿时再次清洗，阻断存储型 XSS。
3. 生产环境启动时拒绝默认数据库密码、默认 JWT 密钥和通配 CORS 配置。
4. 统一 `moderator` 审核管理员角色的代码注释和项目文档。
5. 消除推荐路由层之间的反向调用，把推荐业务逻辑收敛到 service 层。

## 数据结构

- 不新增数据表，不修改现有表结构。
- 已有文稿正文不做破坏性批量重写；详情接口返回正文时执行清洗，后续编辑保存时写回清洗后的 HTML。

## 接口契约

- 现有 REST 路径、请求字段和成功响应保持不变。
- 文稿创建、编辑和导入接口会删除正文中的危险标签、事件属性与危险 URL。
- 新增环境变量：
  - `APP_ENV`：`development` 或 `production`，默认 `development`。
  - `CORS_ORIGINS`：英文逗号分隔的允许来源；开发默认允许本机 Vite 地址。
- `APP_ENV=production` 时，若仍使用默认数据库密码、默认 JWT 密钥、过短 JWT 密钥或 `CORS_ORIGINS=*`，应用启动失败并给出中文错误。

## 前端交互

- 不改变页面结构和交互。
- 富文本中的段落、标题、列表、链接、图片和表格继续正常展示；脚本、内嵌页面、事件处理属性和危险协议会被移除。

## 实现切片

1. Docker 构建上下文与环境配置保护。
2. HTML 允许列表清洗服务、写入链路与历史读取兜底。
3. 推荐逻辑下沉 service、角色与部署文档同步。
4. 后端单元测试、Python 静态检查、前端构建和 Git 差异评审。

## 成功标准

- Docker 忽略规则不会包含 `backend/.env`，配置示例文件可正常提交。
- XSS 回归测试覆盖 `script`、`iframe`、`onerror`、`javascript:` 和恶意 SVG。
- 生产配置错误能在连接数据库前终止启动。
- OpenAPI 路径不减少，前端生产构建通过。
- 不改动用户已有的模型文件变更，不提交真实 `.env`。
